Data contract

All visible homepage and shared-CTA content now comes from the Atlas API at runtime: text, numbers, image URLs, links, phone values, CTA labels, query-state labels, and contact-form status copy. constants/copy.ts remains only as a seed/type source and is not used as a rendering fallback.

  • Hero media uses the required Atlas API image URL; the published field now points to the production-matching hero-preview.jpg media record rather than the replaced blue-scrubs photo.
  • Payment, medical note, ISMS, apply labels, and CTA labels render the API field directly.
  • Required CTA fields are required by the CMS mapper; missing text is exposed as a visible [missing: ...] marker instead of silently borrowing hardcoded copy.
  • The isolated MICS link field content.micsHref renders a field-specific [cms-field-error: ...] diagnostic when empty or malformed, so that one bad URL does not crash the homepage.
  • The live malformed pricing/pricing-meta.cancellation_href field is isolated the same way: /pricing remains usable and shows [cms-field-error: rates.pricing.cancellationHref (...)] instead of returning HTTP 500.
  • Runtime metadata no longer imports the hardcoded SEO seed module; titles, descriptions, og:image values, and sitemap lastModified continue to come from Atlas, while constants/seo-routes.ts contains only route-to-CMS wiring.
  • The sticky CTA renders the API sticky_request_label directly, including the client-requested お問合せ label.
  • Loading, error, retry, empty, and contact-form status labels are required Atlas fields; missing values surface a visible marker rather than a bundled fallback.
